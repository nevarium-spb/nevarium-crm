# Handoff — Невариум CRM

Читать первым. Проект многосессионный, владелец не программист, поддерживает ИИ-агент.
Полный контекст решения — в памяти проекта (`nevarium-crm-decision`) и `docs/DECISIONS.md`.

## Что это

Единая CRM для всех проектов Невариум. Заявки с форм и чат-ботов сайтов Лаб ИИ (`G:\nevarium1`)
и Визор (`G:\nevarium_vizor`) должны попадать в один инбокс с разбивкой по проектам и источникам.
Код извлечён из почти готовой CRM (см. ADR-001/002). Решение: **дорабатывать, не переписывать.**

## Сделано (Веха 1 — извлечение в отдельный репозиторий) ✅

- CRM вынесена из `G:\nevarium` в `G:\nevarium-crm` как standalone (без маркетингового сайта).
  Оригинал не тронут.
- Новые файлы: `index.html`, `src/main.jsx` (монтирует CrmApp, `/`→`/crm`), `package.json`
  (без framer-motion — CRM его не использует), `.gitignore`, `data/.gitkeep`.
- **Проверено:** `npm test` — 49/49 проходят; бэкенд стартует; вход `demo@nevarium.ru` / `demo12345`
  работает; дашборд с демо-данными рендерится (воронка, лиды, задачи).
- Git: закоммичено и запушено — https://github.com/nevarium-spb/nevarium-crm (ветка `main`,
  коммит `0a47024`).

## Сделано (Веха 2 — модель проекта) ✅

- Миграция v3 в `server/db.js`: справочник `projects` (slug, display_name) + `project_id`
  на `contacts` и `deals`. Два проекта: `nevarium1` / «Невариум Лаб ИИ»,
  `nevarium-vizor` / «Невариум Визор». Решение по схеме и его причины — ADR-005.
- `server/app.js`: `project_id` в `ENTITIES` (generic CRUD протаскивает сам),
  `resolveProjectId()` понимает slug и id, фильтр `GET /api/crm/<entity>?project=`,
  read-only `GET /api/crm/projects`, сделка наследует проект контакта,
  неизвестный проект → 400. Демо-данные разнесены по обоим проектам.
- **Проверено:** 56/56 тестов (было 49, добавлено 7, включая миграцию на непустой базе);
  миграция прогнана на реальной `data/dev.sqlite` — версия 2→3, счётчики совпали,
  все старые строки получили «Лаб ИИ», строк без проекта нет; фильтр по обоим проектам
  отдаёт верное; сборка фронта и интерфейс не сломались.

## Следующий шаг (Веха 3 — приём заявок с привязкой к проекту)

1. `POST /api/leads` принимает проект (slug в теле; можно подстраховаться Origin →
   allowlist доменов обоих сайтов). Контакт и сделка получают `project_id`.
2. CORS-allowlist на публичный эндпоинт.
3. **152-ФЗ:** обезличить Telegram-уведомление — сейчас в payload `outbox` лежат имя и
   контакт (проверено). Оставить проект + источник + ссылку в CRM, без ПДн.
4. Тест: заявки обоих проектов приходят в свои проекты.

Дальше вехи 4–6: фильтр в инбоксе/списках (UI); дашборд/аналитика по проектам
(~8 запросов в `app.js`); подключение сайтов + деплой + политика ПДн.

## Заблокировано на владельце (не код, блокирует только деплой — Веху 6)

- **Хостинг решён: Timeweb Cloud** (ADR-004 в `docs/DECISIONS.md`) — дешевле Яндекс.Cloud
  в 3,5–5 раз на нужной конфигурации, есть готовый PaaS-режим Cloud Apps под Docker+SQLite.
  Осталось: владельцу создать аккаунт на timeweb.cloud (создание аккаунтов — не моя зона).
- Домен/поддомен для CRM (например, `crm.nevarium-lab.ru`).
- Telegram-бот через @BotFather + chat_id — для уведомлений.
- Уведомление РКН + юрлицо Визора (тот же ИП Макеева М.А. или отдельное лицо?).
