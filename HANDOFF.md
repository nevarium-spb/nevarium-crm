# Handoff — Невариум CRM

Читать первым. Проект многосессионный, владелец не программист, поддерживает ИИ-агент.
Полный контекст решения — в памяти проекта (`nevarium-crm-decision`) и `docs/DECISIONS.md`.

## Что это

Единая CRM для всех проектов Невариум. Заявки с форм и чат-ботов сайтов Лаб ИИ (`G:\nevarium1`)
и Визор (`G:\nevarium_vizor`) должны попадать в один инбокс с разбивкой по проектам и источникам.
Код извлечён из почти готовой CRM (см. ADR-001/002). Решение: **дорабатывать, не переписывать.**

## Сделано (Веха 1 — извлечение в отдельный репозиторий) ✅

- CRM вынесена из `G:\nevarium` в `G:\nevarium-crm` как standalone (без маркетингового сайта).
  Оригинал не тронут.
- Новые файлы: `index.html`, `src/main.jsx` (монтирует CrmApp, `/`→`/crm`), `package.json`
  (без framer-motion — CRM его не использует), `.gitignore`, `data/.gitkeep`.
- **Проверено:** `npm test` — 49/49 проходят; бэкенд стартует; вход `demo@nevarium.ru` / `demo12345`
  работает; дашборд с демо-данными рендерится (воронка, лиды, задачи).
- Git: репозиторий пока **без коммита** — ждём решения владельца по коммиту и созданию GitHub-репо
  (правило: не коммитить/пушить без просьбы).

## Следующий шаг (Веха 2 — модель проекта) — делать первой из фич

Самое рискованное (данные), поэтому первой:
1. Миграция в `server/db.js`: таблица `projects` (id, slug, display_name, created_at) +
   `project_id` на `contacts` и `deals` + backfill всех существующих строк в проект «Невариум Лаб ИИ».
2. Сид двух проектов: `nevarium1` / «Невариум Лаб ИИ», `nevarium-vizor` / «Невариум Визор».
3. Добавить `project_id` в `ENTITIES.contacts.fields` и `deals.fields` (`server/app.js`) — generic
   CRUD протащит автоматически.
4. Тест: старые демо-данные не потеряны, у всех проставлен дефолтный проект; фильтр по проекту отдаёт верное.

Дальше вехи 3–6 (см. список задач / память): приём заявок→проект + обезличить Telegram; фильтр в
инбоксе/списках; дашборд/аналитика по проектам (8 запросов); подключение сайтов + деплой + 152-ФЗ.
